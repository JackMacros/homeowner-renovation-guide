# 现场留证、变更与问题闭环

[返回专题总览](index.md)

## 留证的目的

记录不是为了和工人对抗，而是为了让所有人知道：做了什么、用了什么、哪里被遮住、谁确认过、问题是否已经解决。

好的记录能同时服务于验收、结算、维修和未来打孔改造。

## 推荐目录结构

```text
装修项目/
├─ 00-合同与报价/
├─ 01-设计图纸/
├─ 02-材料订单与票据/
├─ 03-施工进度/
├─ 04-隐蔽工程照片/
├─ 05-阶段验收/
├─ 06-现场变更/
├─ 07-问题整改/
├─ 08-设备说明与保修/
└─ 09-最终结算与交付/
```

每个阶段再按房间或日期分目录。云端和本地至少保留两份。

## 文件命名

推荐格式：

`日期-阶段-房间-方向或位置-内容-序号`

例如：

`2026-10-09-水电-厨房-北墙-插座与给水定位-01.jpg`

不要大量保留 `IMG_1234.jpg` 而不分类。

## 隐蔽照片怎样拍

每个位置至少拍：

1. 能辨认房间和方向的全景；
2. 能看清连接和材料的近景；
3. 带卷尺或固定基准的尺寸照片；
4. 材料包装和完整型号；
5. 测试过程和结果；
6. 封闭前最终状态。

水电照片尽量正对墙面拍摄，并记录管线距墙角、地面或顶部的尺寸。吊顶内部按房间连续拍摄，避免只拍几个漂亮节点。

## 施工群使用规则

施工群适合记录：

- 当日计划与完成情况；
- 材料到场及验货；
- 图纸、尺寸和工艺确认；
- 问题照片；
- 变更的价格和工期；
- 验收、整改和复验结果；
- 下一工种进场条件。

关键事项用完整句子确认，不只发语音或“好的”。例如：

> 确认厨房北墙插座向东移动150毫米，按完成墙面定位；增加费用为……，工期影响为……；修改后请同步更新水电点位图。

## 变更单模板

每次变更至少记录：

- 编号和日期；
- 原图纸或原约定；
- 变更原因；
- 变更后的内容和尺寸；
- 涉及材料和工艺；
- 增减工程量和费用；
- 对工期及其他工种影响；
- 需要重新验收的内容；
- 提出人、执行人和确认人；
- 更新后的图纸或现场照片。

先确认再施工。没有价格和影响说明的变更，后期最容易产生争议。

## 问题单模板

```text
问题编号：
发现日期：
房间与位置：
问题描述：
现场照片：
判断依据或约定效果：
责任方：
整改方案：
完成期限：
整改后照片：
复验方法：
复验结果与日期：
```

一个问题一个编号。不要把十几个位置合并为“墙面有问题”。

## 问题优先级

### 立即停工

- 疑似结构破坏；
- 燃气、电气或其他明显安全风险；
- 持续漏水；
- 即将被覆盖的重大隐蔽缺陷；
- 施工方案与确认内容严重不符。

### 覆盖前必须整改

- 水电、防水、吊顶内部和基层问题；
- 影响后续尺寸和安装的偏差；
- 材料型号不符；
- 测试未完成。

### 完工前集中整改

- 小范围划伤、污染；
- 柜门、五金调整；
- 墙面局部观感和收口；
- 不影响后续施工的轻微问题。

优先级低不代表可以删除，只是安排不同整改时点。

## 整改闭环

完整闭环为：

> 发现 → 编号 → 确认责任 → 确认整改方案 → 保护周边 → 整改 → 重复原检查 → 记录复验 → 关闭问题

以下都不算问题关闭：

- 工人回复“知道了”；
- 现场看起来已经动过；
- 问题被下一工序遮住；
- 没有重复原测试方法；
- 仅口头承诺入住后再修。

## 工种交接记录

上一工种离场时记录：

- 完成范围；
- 未完成和待整改事项；
- 已完工程的保护要求；
- 隐蔽位置和禁止打孔区域；
- 下一工种使用的基准尺寸；
- 剩余材料和现场垃圾；
- 交接照片和日期。

下一工种确认后再施工。发现上一工种问题应立即提出，不能默默覆盖后再推责。

## 最终资料包

项目结束后，将零散记录整理成：

- 最终版图纸；
- 材料和设备清单；
- 隐蔽工程照片册；
- 给水、防水、电气和设备测试记录；
- 全部变更及最终结算；
- 已关闭和仍观察的问题；
- 保修联系人和期限；
- 备用材料存放位置；
- 阀门、配电回路、滤芯和设备维护说明。

这份资料包应让未来维修人员在不了解施工过程的情况下，也能快速找到管线、型号和责任信息。
